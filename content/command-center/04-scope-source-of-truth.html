1. Live today

Command Centre is the owner-facing conversational layer — ask it anything about the salon and it pulls live data, drafts the change, or hands off to a human. The total exposed action surface today is 137 actions, split across 14 areas. (Do NOT say "230+" — the correct number is 137.)

2. Live — but read the caveat

Bulk-destructive actions = per-item confirmation

COMPLIANCE NOTE

Destructive bulk actions require per-item confirmation rather than a single blanket approval. This is a known design choice — pitch it as a safety feature, not a friction point: "if you ask to cancel ten appointments, Command Centre walks you through them one-by-one rather than nuking the lot on one tap."

4. Out of Scope (do NOT promise)

DON'T PROMISE

Anything outside the 137 actions listed in section 1 is out of scope today. Command Centre is a query-and-act layer for the data the owner already owns on their active location — not an open agent that can reach external systems or other tenants.

DON'T PROMISE

Cross-location bulk operations beyond "switch active location." Multi-location is supported by switching context, not by simultaneous fan-out.

DON'T PROMISE

Single-tap blanket approval of bulk-destructive actions — by design, every item in a destructive bulk gets its own confirmation.

7. Key terms (glossary)

  • Command Centre — the conversational layer that opens from the top-right of any page in the web dashboard.
  • Action type — READ — a look-up that never changes anything.
  • Action type — WRITE — a change that opens a consent card with current + new values before pushing.
  • Action type — SWITCH / ROUTE — changes context, opens links, or routes the owner to a human.
  • Consent card — the inline preview a WRITE action opens before the change is actually pushed.
  • Composite business snapshot — a single query that pulls calendar + services + reviews + leads + GBP gaps + ranking + billing in one response.
  • Cross-tenant isolation — the guarantee that 0 data is shared across owners. Tested security surface.
  • Bulk-destructive per-item confirmation — the deliberate design choice that destructive bulk actions require per-item approval rather than a single blanket tap.
  • Active location — Command Centre only touches data on the active location; multi-location chains switch context by name.
